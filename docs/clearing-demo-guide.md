# 清算升级课程演示指南

这份操作稿展示申请与确认编号、后台任务进度、错误净值重新清算、按归属日生成模拟TA文件。所有银行卡、资金和TA均为平台内模拟。实际验收状态见[需求验收矩阵](requirements-test-matrix.md)，本操作稿的预期结果不能替代测试记录。

管理员和客户使用不同浏览器或普通窗口与隐私窗口。同一浏览器的普通标签页共享登录会话。项目数据持久保存，不清库、不倒退旧客户业务时间。

样例从2026年11月2日周一14:00开始，参考净值日10月30日，首次确认与重清日11月3日。如果当前业务时钟已经晚于起点，选新的未来开放周一，并把整套参考日、申请日、确认日一起替换；在“产品与数据 → 交易日历”核对全部日期为开放日。编号序列、卡标识和ID由系统生成，不照抄下文或其他客户的值。

旧订单即使可以查询，也可能没有可靠受理快照、确认轮次或扩展权益输入。出现“历史确认编号未采集”或历史缺失阻断时使用新客户、新产品和新业务范围；不能把基线前旧记录直接重清，更不能补造历史来让预演通过。

## 2 准备双卡申请与业务编号

管理员进入“运营与审计 → 业务时钟”，设为2026-11-02 14:00:00。在“产品与数据 → 产品规则 → 新建基金类别”创建以下专用产品：

| 字段 | 输入 |
| --- | --- |
| 基金类别代码/名称 | CL261102A / 清算演示债券 A，重复时换新后缀 |
| 类型/管理人/登记机构 | BOND债券 / 课程模拟资产管理 / 模拟登记机构一 |
| 风险/运作状态 | R2 / OPEN开放交易 |
| 申购费率/赎回基础费率 | 0 / 0；不增加额外费率档位 |
| 最低申购/最低赎回 | 100.00元 / 1.0000份 |
| 开放开关 | 申购、赎回均开启 |

新产品默认15:00截止、T+1确认。进入“净值发布”，先发布该产品2026-10-30的参考净值1.000000，用于投资者报价预估。

客户在登录页注册并登录新账号，进入“账户设置 → 客户档案”开通模拟账户，完成十道风险测评；可每题选择第三项，使风险等级与R2匹配。进入“银行卡与资金”添加模拟工商银行A卡及模拟建设银行B卡，持卡人均为“清算演示客户”。首张有效卡得到100000.00元模拟余额，第二张初始0.00元；给B充值1000.00元。

记录A、B的SIM标识和交易账户编号。在“基金市场”找到专用产品，分别明确选择A、B交易账户，预估并提交申购：

| 账户 | 申请金额 | 受理后可用现金 | 冻结现金 |
| --- | ---: | ---: | ---: |
| A | 1000.00 | 99000.00 | 1000.00 |
| B | 500.00 | 500.00 | 500.00 |

在“交易记录”刷新，记录两笔申请编号：格式为20261102加6位每日序列，共14位，平台其他申请会占用序列，所以不要求结尾恰好000001/000002。两笔申请号不同且归属日均为2026-11-02。此时还没有成功确认编号，不能把订单UUID当作确认号。

可选撤单样本：A额外申购100.00元，在15:00前立即撤销。两笔主线申请保留；后续申请文件应排除此撤单，并记录排除数。

## 3 已确认结果与异步任务

管理员推进业务时钟到2026-11-02 15:10:00，在“净值发布”发布专用产品申请日2026-11-02的净值1.000000。此时先按第5节生成当日申请文件并保存SHA-256，以展示在15:30建议截止前完成。然后推进到2026-11-03 09:10:00，进入“交易与任务 → 任务中心”，选CONFIRM，业务日期明确填2026-11-03，点“执行任务”。

先记录任务ID并看节点进度。QUEUED/RUNNING表示已受理并处理中，零计数不会表示无工作；等任务完成再核对业务结果。可刷新页面或离开后回到“后台运行 → 查询进度”，按同一任务ID继续查询。任务汇总包含其他客户，不要求总数只有2。

客户刷新交易记录与资产：A确认1000.0000份，B确认500.0000份，两卡冻结现金为0，成本分别1000.00和500.00元。打开两笔“详情”，记录当前确认编号、轮次、行情所属日、资产业务有效日和真实处理时间；第一次确认编号日期为本轮处理日2026-11-03。

## 4 修订净值与重新清算

管理员在“产品与数据 → 净值修订”选择专用产品，行情所属日填2026-11-02，修订净值填1.250000，理由填“课程演示 更正已确认申购的错误净值”，保存候选修订。记录修订集合ID；此时客户份额仍是1000/500，候选尚未影响资产。

进入“交易与任务 → 重新清算”，填写候选修订集合ID，点“生成影响预演”。核对来源账户、行情日和原有效日，差异应为：

| 账户 | 原份额 | 更正份额 | 申请金额/成本 | 可用现金 |
| --- | ---: | ---: | ---: | ---: |
| A | 1000.0000 | 800.0000 | 1000.00 | 99000.00 |
| B | 500.0000 | 400.0000 | 500.00 | 500.00 |

预演应READY且无阻断原因。存在不足或历史边界时先阅读明细，不能跳过；超过200条差异用“加载更多差异”。预演后不要给相关账户充值、提现、再申购或更换卡，这些动作可能使输入版本过期；过期时重新生成预演。

点“确认执行重新清算”，记录新的runId并等完成。客户刷新后应见A800.0000份、B400.0000份，原申请金额、申请编号、来源账户/卡、成本和有效日保持。订单详情“确认历史”应同时保留原确认REVERSED与新确认ACTIVE，新确认有新编号和轮次；不会删除旧记录。管理员可在“运营与审计 → 对账”查看结果。

仅保存候选或生成预演不会更改资产；202受理也不等于执行成功。若任务FAILED、预演BLOCKED或版本过期，保留ID和具体原因，按矩阵记录结果，不把未完成写成通过。

## 5 申请文件下载与同快照重导

首次生成在第3节的11月2日15:10执行：管理员进入“交易与任务 → 申请文件”，业务日期填原申请归属日2026-11-02，登记机构选专用产品的源TA，点“生成申请文件”。当前时钟已过封账点；如果改用其他样例日，需先到所涵盖产品最晚截止后5分钟，而不是只假定15:05。若选择次日补导，完成时间会如实晚于原日建议截止，文件仍可校验和下载；不要把补导展示成当日准时生成。

记录exportId与runId，页面会跟踪后台运行。等待封账/导出步骤完成后，再点“申请文件”页签并刷新列表。完成行显示快照版本、行数、金额/份额汇总和SHA-256；真实开始/结束时间在运行进度中查看。点“下载文件”，文件名形如applications_20261102_TA1_v1.csv，其中TA编号以实际产品为准。

文件是该归属日、该源TA全平台申请，可能包含其他客户；按两笔申请编号定位样本。核对17列表头、源交易账户/模拟卡、原申请金额1000.00/500.00，申购的application_shares两行均为空，即使已经确认并重清也不能写800/400。若做过撤单样本，它不进入有效行。不要使用投资者交易记录的个人“导出CSV”替代本文件。

完成第4节重清后，在同一导出行点“重导同一快照”，记录新的任务ID并等完成，重新进入“申请文件”页签刷新后再下载。exportId与snapshotVersion保持，SHA-256应与首次一致，保存的两次文件大小也应相同；重导读取原快照，后续确认、改产品名称或换卡不改变历史文件。次日重导的完成时间与首次不同，原申请字段和文件内容保持。文件未完成或只有.part时应没有可用下载结果。

CSV中的编号按文本导入表格软件，避免前导零丢失或显示科学计数法。文件含模拟账户信息，作为本地课程材料保管。

## 6 可选异常与角色展示

份额不足场景用另一位新客户和另一只专用产品单独演示：无费申购1000.00元、以净值1确认1000份，在之后的开放日申请赎回900份，再修订原申购日净值为1.25。原申购只能得到800份，无法保持原900份赎回，预演应BLOCKED并说明不足；旧份额/冻结/确认保持，不能借用未来买入或另一卡。不要把该后续赎回加入前面成功样例。

已支付并已提现的现金不足、转换/分红/收益的跨日依赖和进程恢复依照测试矩阵另验，不用现场删除数据或强行透支制造演示。已完成清盘、旧权益输入缺失等明确阻断边界保留旧结果。

操作员可处理标准任务及申请文件，无权执行净值修订或重新清算；管理员可处理这两项。若展示操作员，按原演示指南由管理员创建新操作员并首次改密，不假定固定操作员已存在。普通投资者只可查本人确认历史，不能下载全平台TA文件。

课程截图建议保留四组：双卡申请编号及冻结、任务ID与节点进度、预演差异与旧/新确认历史、文件快照与两次一致的SHA-256。性能要求需要独立测量报告；页面看起来流畅或只有两笔交易不能证明并行性能达标。
