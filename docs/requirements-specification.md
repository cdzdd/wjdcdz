# 恒生基金业务模拟平台需求规格说明书

版本：1.0；需求基线日期：2026年10月13日；课程：创新实践3；小组：；成员：。

本规格保留基金销售与多模拟银行卡的既有业务，接受申请及确认编号、清算资源隔离、错误行情重新清算、当日申请文件四组改造需求。它用于课程设计、实现和验收；接受的目标需求不等于已实现或已验收。资源与模拟TA协议为本项目采用的课程建议，不能表述为老师规定或实测成绩。

## 1 引言

### 1.1 编写目的

为教师、小组开发人员、测试人员和演示操作人员定义业务边界、输入输出、异常、权限和可验收结果。后续设计、接口和测试使用同一需求编号；实现证据记录到验收矩阵，未完成测试的条目不能标为通过。

### 1.2 目标与背景

项目名称为恒生基金业务模拟平台，简称基金模拟平台；项目编号不适用。任务提出者为课程教师；开发者为课程小组，具体小组和成员在封面暂留空；用户为教师、学生投资者和管理员。项目是独立教学系统，通过浏览器演示场外公募基金销售、账户资金与份额、登记确认及后台处理。

前端Vue网站向Spring Boot后端发送HTTP/JSON；后端使用MySQL记录账户、申请、持仓、流水和审计。银行资金、卡和TA均为内部模拟，净值由管理员录入或演示生成，TA申请文件落本地文件并提供受控下载。不接真实银行、真实资金或真实TA，不定义SFTP、真实回执或监管报送。

### 1.3 假定和约束

继续使用模块化单体、同一MySQL及既有Vue/Java技术。保留开户、适当性、多卡账户、充值提现、申购赎回、认购、定投、分红、货币收益、转换、换卡、清盘、通知和审计。不得自动借用另一张卡，不产生负现金、负份额或超冻结，不删除旧确认及账务历史。

原申请金额或份额、归属日、交易账户、来源卡、TA关系、费率及风险快照在确认和重清时保持。历史UUID订单号、主键、幂等键继续可读；它们不能替代业务编号。旧确认资料不完整时显示“历史确认编号未采集”，不补造时间或账务。V1至V13历史迁移不改写，升级先在独立测试库验证，演示库升级前备份并对账。

| 冲正 | 新增与旧效果相反的流水，再追加新结果；保留原记录 |
| 封账快照 | 在明确准入边界下固定当日有效申请及来源字段 |
| P95 | 95%的有效请求耗时不高于的响应时间 |

## 2 需求综述

### 2.1 系统用户范围

| 用户 | 职责与权限范围 | 特点与频度 |
| --- | --- | --- |
| 投资者 | 自己的开户、测评、卡、资金、申请、持仓及偏好 | 学生演示或学习时使用；不能读取他人资金或后台任务 |
| 操作员 | 产品/行情维护、批次操作和业务查询 | 按现有角色授权；仅在后端允许的职责内操作 |
| 管理员 | 用户管理、配置、审核、清算、重清、导出、对账及审计 | 每个业务日或课程演示时使用；敏感动作记录发起人及理由 |

| 维护人员 | 本地运行、日志、备份恢复与升级 | 在维护窗口操作；不获得隐含的投资者业务权限 |

具体角色检查由后端完成，页面隐藏菜单不能替代授权；客户跨账户操作需验证同属当前用户。小组成员和组织结构不影响业务权限模型。

### 2.2 业务流程分析

正常申购流程：注册登录 → 开户与风险测评 → 添加模拟卡及充值到该卡交易账户 → 查看基金和预估报价 → 受理原申请并冻结资金 → 取得申请编号 → 导入申请所属日净值 → 到期确认并取得确认编号 → 持仓及流水归属原交易账户。报价为预估，确认才生成成交结果。

正常赎回流程：选择交易账户及基金 → 按持仓批次校验/冻结请求份额 → 截止前可撤单释放冻结 → 到期按规则和净值确认 → 产生应付款 → 模拟回款至原账户/受款绑定 → 查看到账或阻断原因。组合赎回按用户明确给出的各账户份额分配，不自动跨卡。

认购受理后等待募集成立或失败；成立生成初始份额和相应利息结果，失败退款。定投按计划生成普通申购并保留执行记录；分红按登记日权益产生现金或再投资；货币收益按自然日规则计提/结转并处理退出尾差；转换按允许配对在同一交易账户内从源基金转向目标基金，保存双方TA，不要求同TA。换卡经后台审核，更新未来绑定，旧申请来源不变。清盘结算、现金差额更正和常规撤单沿用各自范围，不能冒充重新清算。

固定清算支路：申请归属日 → SEAL_APPLICATIONS封账 → EXPORT_APPLICATIONS导出；交易到期支路：IMPORT_MARKET行情 → CONFIRM确认 → PAY付款 → RECONCILE对账。确认处理日扫描到期申请并采用各申请行情日；ALL仅运行当前可运行节点，尚未到封账时点不阻断其他到期业务。SIP、MONEY保留为独立业务任务。

重清分支：提交带理由的行情修订集合 → 定位旧确认与后续依赖 → 固定输入水位并预演差异 → 份额/资金不足或跨清盘则BLOCKED，旧结果保留 → 可行时短暂锁定影响账户资产写入 → 核对版本未漂移 → 同一发布事务追加旧效果冲正和新效果 → 切换当前有效行情/确认 → 对账及通知。无关账户继续实时交易。原申请不重新受理，定投不重复生成。

### 2.3 功能综述

系统边界：投资者与管理员浏览器 → 网站及API → 账户/产品/交易/清算模块 → MySQL及本地文件。模拟银行、模拟TA处于系统内部；外部真实资金和TA传输不适用。

```text
投资者浏览器 ─┐
              ├→ Vue网站 → HTTP JSON API → 账户 产品 交易 清算 → MySQL
管理员浏览器 ─┘                                    └→ 模拟TA申请文件
                           系统内模拟银行与TA，不连接外部真实资金
```

| 模块 | 主要功能 | 范围 |
| --- | --- | --- |
| 身份与账户 | 登录、开户、测评、多卡、充值提现 | 保留BIZ-001至BIZ-002 |
| 产品与普通交易 | 产品报价、收藏、申购赎回、撤单、组合赎回 | 保留BIZ-003至BIZ-004 |

| 后台与审计 | 换卡、清盘、现金更正、管理与通知 | 保留BIZ-008至BIZ-009 |
| 业务编号 | 统一申请编号和各轮确认编号 | 新增NUM-001 |

## 3 功能需求

### 3.1 身份与账户

功能概述：用登录身份、风险等级和独立卡账户明确交易权限与资金来源。

#### 3.1.1 登录开户与适当性 BIZ-001

状态A，优先级1，提出人课程小组。前置条件为服务可用；注册输入用户名、密码、显示名，登录输入凭据，开户输入开户请求，风险测评输入10项1至5分答案；本人修改密码输入旧/新密码。处理为认证、状态检查、会话建立、密码修改、开户及测评有效期保存；所有写请求校验CSRF。投资者仅操作本人，管理员可按权限启停用户、建立操作员及重置临时密码；重置后注销旧会话并要求修改密码。被禁用、密码错误、参数非法、测评未完成/过期应明确拒绝，不能建立交易资格。

输出为用户、角色、开户状态、风险等级/有效期及成功或错误消息。界面参考为现有登录、账户及风险测评页面。验收BIZ-T01：正确与错误登录、注销、CSRF、修改/重置密码及旧会话失效、操作员权限、重复开户、测评有效期及跨用户拒绝；USB Key、登录机构代码与8位密码框示例不适用。

#### 3.1.2 模拟卡账户与资金 BIZ-002

状态A，优先级1，提出人课程小组。前置条件为本人已登录及开户；输入银行名称、持卡人、请求键，以及明确交易账户的充值/提现金额、默认卡或启停/解绑操作。处理为创建模拟卡及交易账户、验证归属和卡状态、独立管理可用/冻结余额与TA基金账户、追加资金流水。默认卡只提供选择偏好，不给后续操作隐式跨卡扣款权限。

输出为模拟卡号、交易/基金账户、绑定版本、逐账户余额及流水。余额不足、卡禁用、重复请求、未了冻结或受款异常按规则拒绝/等待，重复请求不双扣。界面参考为卡管理、充值提现及资金流水。验收BIZ-T02：双卡资金隔离、提现不足、默认卡切换不改旧来源、幂等及不可越权；资金合计与流水一致。

### 3.2 产品与普通交易

功能概述：按产品规则受理申请，区分预估、冻结、确认和付款状态。

#### 3.2.1 产品查询与管理 BIZ-003

状态A，优先级1，提出人课程小组。输入基金/份额类别、历史日期、收藏动作；管理员输入代码、名称、类型、管理人、TA、风险、费率、限额、状态和开放开关，以及交易日历、净值或CSV。查询用户可看产品，收藏仅本人；维护需后台授权。处理为展示产品与历史、保存规则版本；净值普通入口不能直接覆盖已发布/使用的行情，错误行情走RCL-001。

输出为产品详情、行情、费率和规则状态；非法金额/精度、重复代码、无效日期或禁止覆盖应拒绝，缺行情显示等待原因。界面参考为基金列表/详情、后台产品/行情。验收BIZ-T03：查询与收藏、规则快照、权限、交易日历、缺净值等待及普通覆盖保护。

#### 3.2.2 申购赎回与撤单 BIZ-004

状态A，优先级1，提出人课程小组。前置条件为开户、有效测评、产品开放、账户/卡及绑定版本有效；输入业务类型、基金、交易账户、卡、绑定版本、申请金额或份额、请求键；组合赎回输入显式账户份额分配。处理为报价预估、风险及限额校验、按截止和日历归属申请、冻结原账户资金或批次份额、到期确认及回款。申请/确认编号遵循NUM-001。撤单仅截止前且未确认申请释放冻结。

输出为订单、原来源、状态、日期、净值、费用、份额、应付款及到账流水。非法/不足/重复/绑定版本过期请求明确拒绝或返回原结果，缺净值等待，不自动改用其他卡，已确认订单不得普通撤销。界面参考为交易、订单、持仓与到账页面。验收BIZ-T04：双卡申购和赎回全流程、截止日切、组合分配、冻结与批次、费率/持有期、缺行情、幂等、撤单边界及对账。

### 3.3 扩展业务

功能概述：维持原账户和来源快照，将扩展业务的确认、资金和份额纳入统一账务。

#### 3.3.1 认购与定投 BIZ-005

状态A，优先级1，提出人课程小组。投资者输入认购基金、原账户/卡/绑定版本、金额和请求键，或定投基金、金额、频率、日、起始日及状态。管理员输入募集成立/失败、结束日、初始净值和利息规则。处理为认购冻结、募集结果形成份额/退款；定投按计划到期生成普通申购，并可暂停/终止。募集处理与定投执行进入CLR-001后台通道，客户受理仍实时执行。

输出为认购状态、份额/退款、定投计划和每次执行结果；非募集产品、资金不足、参数非法或不可执行计划记录原因，不跨卡补扣，不重复生成。界面参考为认购、定投与后台募集结果。验收BIZ-T05：成立/失败、利息、暂停恢复、余额不足和同次执行幂等；编号和文件只计定投生成订单一次。

#### 3.3.2 分红与货币收益 BIZ-006

状态A，优先级1，提出人课程小组。投资者输入分红方式；管理员输入基金、登记/除权/付款日、每份分红，或自然日万份收益和年化收益。处理为按登记权益生成快照、现金分红/再投资、自然日收益、退出结转和尾差；批量执行进入CLR-001。权限区分本人偏好和后台权益维护。

输出为权益、分红、收益、份额/付款、账务有效日及执行状态。日期非法、行情缺失、重复执行等应明确拒绝/等待或返回已完成结果；原来源不丢失，尾差不重复计算。界面参考为分红偏好、收益明细及后台权益。验收BIZ-T06：两种分红、跨自然日收益、清仓尾差、重复执行，以及RCL-001重清保留登记日和持有期。

#### 3.3.3 基金转换 BIZ-007

状态A，优先级1，提出人课程小组。前置条件为允许配对、同一交易账户有可用源份额；输入源/目标基金、账户、请求份额、请求键。处理为冻结源批次、按双方行情及规则确认目标份额和费用，保留源/目标TA与来源卡。不得新增“必须同TA”限制。

输出为转换申请、NUM-001编号、确认、分配及资产结果；不支持配对、份额不足或行情未齐时拒绝/等待，重复请求不双转。界面参考为转换及转换记录。验收BIZ-T07：同账户转换、跨TA配对、来源批次/费用、缺行情、重复请求及重清后依赖份额不足的整体阻断。

### 3.4 后台管理与查询

功能概述：用审核、对账和审计约束后台资产操作，并给用户提供可理解的结果。

#### 3.4.1 换卡清盘与现金更正 BIZ-008

状态A，优先级1，提出人课程小组。投资者输入换卡银行、持卡人和理由；管理员输入审核理由、受款可用状态、终止产品、清盘价格/日期/理由，或原入账/提现流水、差额、理由、请求键。处理为审核绑定版本、模拟付款受款检查、清盘结算、关联原记录追加现金差额。清盘批量执行进入CLR-001；现金更正不覆盖原流水、不替代行情/完整资产重清。

输出为审核、受款状态、清盘记录或关联差额流水；未授权、原记录不适用、余额不足、受款阻断和重复请求应明确处理，不改历史来源卡。界面参考为换卡、付款、清盘和现金更正。验收BIZ-T08：审核前后来源、付款阻断恢复、清盘资产、原记录不变及重复差额不生效。

#### 3.4.2 资产查询通知与审计 BIZ-009

状态A，优先级2，提出人课程小组。输入本人账户筛选、订单/流水下载、消息已读；管理员输入用户状态、公告和后台查询筛选。处理为逐账户持仓与现金、待付款、订单、转换、任务历史、公告、通知和审计查询，管理操作记录行为、对象、理由、操作者和时间。个人CSV只导出本人记录，与EXP-001全平台申请文件分开。

输出为查询结果、CSV、通知、审计与对账问题；越权拒绝、空记录显示空状态、请求失败可定位请求ID，不能以当前生效投影隐藏旧确认/冲正历史。界面参考为资产、记录、通知和后台总览。验收BIZ-T09：本人/他人授权边界、个人CSV、公告/已读、管理员查询、审计完整性及资产汇总一致。

### 3.5 新开发要求

功能概述：四条老师要求分别形成一个优先级1的接受需求，并与固定节点和可验证结果关联。

#### 3.5.1 统一申请与确认编号 NUM-001

需求描述：所有成功受理交易申请及每轮成功确认各有业务编号。状态A，优先级1，提出人课程教师，对应原要求第1条。

前置条件：交易受理/确认满足既有业务校验，编号日期为开放日。输入为编号类别APPLICATION或CONFIRMATION、业务日期、来源类型/ID和清算轮次；调用由受理服务或后台确认服务完成，不开放让投资者指定号码。处理在事务内使用两套每日全平台序列，格式为8位日期加6位序列，从000001开始。同类跨订单/转换和客户唯一；两类允许同文本但业务类别必填。定投只使用生成订单的一次申请编号，重试返回原号，等待和未成功确认不产生有效确认号。超过999999需明确拒绝，不能截断或回绕。

输出为申请编号、确认编号及其类别/日期、来源、轮次和当前确认引用；旧orderNo和主键保留。重清新确认取得新号并关联旧确认，原有效日不变。权限随原申请/确认，查询仅本人或后台授权。非法类别、非工作日、溢出和冲突必须拒绝并回滚，历史缺号如实标记。

界面参考：投资者订单/转换详情、后台申请/确认及EXP-001文件。验收NUM-T01：同日双卡、多客户、订单/转换并发唯一且14位补零，跨日重置。NUM-T02：重复请求和等待不增加有效号码，失败事务无孤立有效编号。NUM-T03：非工作日顺延、溢出保护、历史可读、重清新号与原有效日区分。

#### 3.5.2 持久化清算与资源隔离 CLR-001

需求描述：清算后台执行的资源占用受限，申购赎回实时路径达到5.2的并行性能门槛。状态A，优先级1，提出人课程教师，对应原要求第2条。

输入为任务类型、业务日期、参数、发起人及请求幂等键；权限为后台授权角色或系统任务，提交与正式执行均校验。处理先持久记录再入有界执行通道，初始建议1工作线程、队列4，实时池8连接、清算池2连接，同库且共用正确路由事务管理器。入事务前选路由、事务内不切换、退出清理身份/时钟/路由。行情改按产品及行情日短事务；候选按稳定游标每页200条，不用会随状态变化漏单的OFFSET。

固定节点为封账、导出、行情、确认、付款、对账。手动与自动任务、募集结果、分红和清盘批次都进入同一通道；不能保留同步旁路。输出为202受理、runId、节点、进度、成功/等待/失败数、业务时间、真实时间、原因和审计。状态为QUEUED、RUNNING、WAITING、COMPLETED、NO_WORK、FAILED、INTERRUPTED、REJECTED；重清预演另有BLOCKED。

请求键永久幂等；活动日/类型/范围只在运行期间占用，终态释放，新键可再次扫描当日新业务，旧键仍返回原运行。队列满返回429并记录拒绝，不能积压成无界队列。重启恢复持久任务，已提交账务不重复。未查明结果的中断任务先恢复/核对，不能提前放行相同范围。节点异常保留原因并可查询/恢复；等待不误标完成，运行中0计数不误标无工作。

界面参考：后台任务列表/详情、节点进度；用户可离开页面后继续查询。验收CLR-T01：手动/自动碰撞、队列满、旧键重试、新键再次扫描和重启恢复。CLR-T02：后台失败完整回滚且不占实时连接配额，线程复用不泄漏上下文，多页无漏项。CLR-T03：同一基金无关账户在清算/导出并行下满足NFR-T02，保留耗时与资源报告；两池不能证明共享数据库绝对零影响。

#### 3.5.3 错误行情重新清算 RCL-001

需求描述：已确认甚至已模拟支付后，重新导入正确行情，撤回旧确认下游资产影响并按新净值重算。状态A，优先级1，提出人课程教师，对应原要求第3条。

前置条件：需要更正的完整可重放历史可用，普通净值覆盖仍受保护。输入为一次修订集合（基金、行情日、新净值）、理由、请求键、预演版本及处理工作日；权限为有重清权限的管理员，普通投资者不能修订。候选修订保存为不可变版本，不立即改变当前资产；多行导入作为整个集合预演，不能漏行。

处理定位受影响确认、付款及截至冻结水位的后续申赎、转换、分红、收益依赖，按资产操作序号和操作内顺序重放原事实。不以跨表自增ID/相同模拟时钟猜因果，不重新受理申请或生成定投。原卡、账户、金额/份额、TA、费率、风险、有效日及持有起点保持。原充值/提现保留为不可重算法事实。

预演输出受影响账户、差额、旧/新净值、现金/份额/冻结/费用/付款/尾差变化和阻断原因。原请求份额不足、支付款已提现而无法回收、跨越已完成清盘、缺完整历史或版本漂移时整体阻断范围，保留旧有效结果和候选集合。禁止自动缩单、透支、跨卡回收或只完成部分账户。

可行发布时给影响账户资产写门禁，短事务锁定并核对输入版本，在同一范围原子追加“旧流水＋同原有效日反向冲正＋新流水”，切换有效行情和确认引用。旧确认/批次失效仅影响投影，不能从全流水加总排除原流水而保留冲正。新确认有独立编号及前一确认关联，旧确认保留REVERSED记录。发布后对账：可用/冻结现金、份额、成本、有效确认、付款及尾差均一致；无关账户保持实时受理。

输出为修订版本、预演ID、运行/节点状态、确认历史、有效资产和对账结果。失败/中断可查询并恢复，未提交结果不生效，已提交结果重试不重复；门禁的范围、理由和恢复状态可见。界面参考为后台行情修订/预演/执行/历史、投资者当前结果及确认历史。

验收RCL-T01：双卡申购/赎回已经确认及支付后修正净值，比较现金、冻结、份额、成本、费用、付款和流水；无费示例1000元从净值1.000000改1.250000应从1000份改800份。RCL-T02：后续赎回/跨TA转换/分红/货币收益按原有效日重放，不重复权益或尾差。RCL-T03：已提现不可回收、原份额不足、清盘边界、历史缺失和版本漂移整体阻断，旧结果保持。RCL-T04：多行修订全覆盖，失败注入/重启/重复请求不半生效、不双冲正，门禁释放且无关账户满足实时门槛。

#### 3.5.4 当日申请封账与导出 EXP-001

需求描述：每工作日约定时点前输出全平台当日有效交易申请，并考虑大规模生成性能。状态A，优先级1，提出人课程教师，对应原要求第4条；具体文件协议是课程建议。

输入为申请工作日、源TA范围、协议/快照版本、时点及请求键；管理员或系统任务有权封账/导出，下载仍需后台授权。处理在产品最晚截止后固定封账准入边界，收齐截止前已提交申请与撤单，处理截止前尚未提交事务，截点后申请顺延。包含申购、赎回、认购、转换及定投生成订单，截止前已撤销排除并计数，已确认申请可历史重导。来源与金额/份额从原申请快照读取，不从可变当前卡/确认结果读取。

按源TA和申请编号游标分页落盘，不拼接完整文件到内存；遵循17字段顺序、UTF-8无BOM、CRLF、文本编号和CSV转义。申购/认购仅原金额，申请份额为空；赎回/转换仅原请求份额。转换保留双方TA，空TA文件仅表头。临时文件核对行数、分业务汇总和SHA-256后原子发布；同快照重导字节相同，新快照另留版本。

输出为导出ID、状态、快照边界、文件、行数、排除数、金额/份额汇总、SHA-256、完成时间和失败原因。未到封账时间为等待，非法日/权限不足/历史字段缺失/磁盘故障明确失败；不发布半文件、不静默遗漏历史。界面参考为后台封账/导出列表、进度、下载/重导；实际接口与协议分别引用第4章和独立协议。

验收EXP-T01至EXP-T04详见模拟TA协议：四业务双卡/定投及源TA完整性，确认后原申请不变，截止事务竞态/换卡/撤单/重导，格式/空文件/失败保护，1万和10万行流式性能。不得用个人历史订单CSV代替。

## 4 接口需求

### 4.1 网站和后端内部接口

网站经HTTP/JSON向后端请求，成功直接返回对象/数组，金融数值为十进制字符串，字段camelCase；错误返回code、message、requestId。写操作传CSRF令牌，会话权限和对象归属由后端检查。现有登录、账户、产品、普通交易、扩展及管理API以 `implementation-contract.md` 与实际控制器为准，本规格不复制可能滞后的路径清单。

新增异步提交输出202及runId，查询输出状态、节点、进度、统计、各类时间及原因；队列满429。任务执行不能使用已结束HTTP请求的会话。重清预演输入修订集合及理由，执行引用预演/版本；查询须保留旧、新确认与当前生效状态。旧同步批次调用方须随异步返回更新，投资者受理结果仍同步返回，不把浏览器等待当作清算事务。

### 4.2 行情和申请文件接口

行情表单或CSV导入的逻辑内容为基金份额类别、行情日和净值；普通首次发布与RCL-001修订集合分开。修订导入需理由、来源及请求键，保存输入版本，验证整集合并给逐行错误；未通过不能部分切换资产。

TA申请输出从系统到本地文件/管理员下载，使用 `interfaces/mock-ta-application-file-v1.md` 的固定17字段、编码、命名、空文件及快照规则。个人订单/资金CSV是独立用户下载接口，不能作为TA文件。真实银行、真实TA、SFTP传输及外部回执不适用，后续如需增加先另定协议和验收。

| 正确性 | 技术错误和重复扣款为0，无漏单/负资产 | 结合请求与流水/资产对账 |
| 正常清算 | 2000笔确认不超过3分钟 | 记录等待/失败原因和实际处理量 |
| 文件生成 | 1万行不超过10秒，10万行不超过60秒 | 分开记录快照和落盘耗时、各阶段堆峰值 |
| 内存 | 批次增量堆不超过64MiB | 固定堆和资源配额，不能只看最终文件大小 |
| 重清并行 | 影响账户短暂门禁可查；无关账户仍达到实时指标 | 同一基金不同账户并行验证 |

NFR-T02：固定软硬件、版本、堆、连接配额和数据脚本，三种场景各测3次并保留P95、吞吐、错误、内存和对账证据。共享数据库CPU/磁盘仍会竞争，“不影响性能”以门槛内实测证明，不承诺绝对零影响。失败或达不到时先记录瓶颈，改变建议值需更新规格并说明原因。

#### 5.2.3 精度需求

NFR-003，状态A，优先级1。金额2位、份额4位、净值6位、费率8位；后端金融计算使用BigDecimal及既定HALF_UP，不能使用二进制浮点。输入按产品限额/精度校验，输出和文件以定长小数字符串传输，中间计算保持BigDecimal并按产品规则在规定步骤舍入。费用及净额、转换目标份额、分红与货币收益沿用现有规则快照，不虚构统一新费率。

金额/份额汇总按已舍入明细对账，尾差按既有规则单独记录；重清须重算并验证尾差而不重复追加。权限随对应业务，非法精度拒绝。验收NFR-T03：边界小数、最小金额/份额、费率、舍入与尾差、CSV/JSON文本往返，以及原/冲正/新流水加总一致。

### 5.3 扩展性需求

NFR-004，状态A，优先级2。通过既有模块边界、产品规则版本和追加迁移支持有限规模增长；新增编号、轮次和文件协议不能破坏历史UUID/来源关联。固定清算节点，不引入微服务、Redis、消息队列、分库分表或通用可编程工作流。更大企业规模、真实TA协议及已完成清盘重放为另行评估范围。

输入为升级前资料与迁移，维护人员执行；输出为兼容查询及资产基线。无法重建历史不能猜造，缺失字段明确提示或阻断。验收NFR-T04：备份后在独立库升级，核对双卡资产/流水/旧订单可读和新申请正常，V1至V13保持不变。

### 5.4 可靠性需求

NFR-005，状态A，优先级1。采用可重启恢复的单机课程容错级别；镜像接管、多物理数据中心容错不适用。账户写入与账务使用事务和幂等，后台任务/节点持久化，进程重启可识别中断并恢复未完成工作；已提交效果不重复。原子发布的重清和导出不能暴露半结果。

维护人员在升级前、课程演示前及重要数据操作后备份，记录时间和位置，并保留最近可验证恢复点；不擅自自动删除备份。监控提供健康检查、任务失败/中断状态和日志请求ID；告警采用后台可见错误及操作员查询，外部短信/邮件告警不适用。恢复时间、备份间隔造成的数据损失以实际恢复演练报告测量并定稿，当前不承诺未验证RTO/RPO数值。

输入为故障和备份，权限为维护/后台角色；输出为恢复状态和对账记录。验收NFR-T05：事务失败、批次中断、重启、重复请求、文件半写及独立库备份恢复，确保结果完整且旧历史保留。

### 5.5 通用界面需求

NFR-006，状态A，优先级2。投资者与后台保持现有统一字体、间距、表单和状态规范；表格展示业务编号、来源账户/卡、申请/行情/处理/有效日及真实时间，金额/份额含单位。加载、空、错误、成功、处理中、等待和阻断状态清楚区分，只显示非零处理数量；排队/运行不能因暂时0条显示无工作。

输入为用户操作和异步进度，权限跟随接口；输出为可读状态和理由。提交防重复，长任务返回任务ID，允许离开后继续查询。取消只用于业务明确允许的截止前撤单；已发布资产任务不提供无定义的中途取消。界面参考为现有页面加后台节点/预演/导出详情。验收NFR-T06：桌面Chrome/Edge、双卡来源、精度显示、加载/空/错误、离开再查、重复点击及长任务状态。

### 5.6 故障处理需求

NFR-007，状态A，优先级1。输入为下列故障，后端/维护角色按范围处理，输出为明确状态、原因、请求/任务ID和可审计恢复结果。

#### 5.6.1 硬件故障

通讯故障：页面保留可重新查询的业务结果，不据超时盲目重新扣款；重试原请求键。应用服务器硬件故障：恢复后查询持久任务及事务结果，核对前不能释放不明状态范围。文件服务器硬件故障：本项目没有独立文件服务器，专用设备不适用；本地磁盘故障应标导出失败并保护旧完成文件。数据服务器硬件故障：停止新的资产写入，维护人员按备份恢复并对账，不自动重建空库覆盖原数据。

#### 5.6.2 软件故障

前台应用程序故障：重新登录/加载后按订单和任务ID查询，后端仍为唯一账务依据。后台服务器故障：保存异常、节点状态和真实时间，事务回滚，恢复只补未完成效果；上下文清理避免影响下一任务。验收NFR-T07：在测试环境模拟连接超时、权限失败、文件写失败、事务异常与重启，核对错误可定位、资产不重复和任务可恢复；真实硬件破坏不作为课程操作。

### 5.7 安全性需求

NFR-008，状态A，优先级1。密码哈希保存，登录会话、CSRF、角色及对象归属检查；SQL参数绑定，导入校验，导出下载验证管理员权限。敏感理由和审计记录发起人，任务线程不继承过期会话。演示账号仅本地配置，公开部署管理员密码从环境配置，HTTPS及Secure Cookie需部署环境实测。

输入为身份、写请求和下载请求，输出为允许结果或权限/校验错误；普通用户不得读他人资产、修改净值或调用后台重清。教学模拟卡标识不存真实卡号；凭据、运行目录、备份和含账户信息文件不提交或对外发布。《需求规格说明书-安全需求指南》未提供具体内容，不宣称符合未知条款。验收NFR-T08：未登录、跨用户、普通用户后台、CSRF、输入/导入校验、下载权限和审计检查。

### 5.8 其他需求

NFR-009，状态A，优先级2。课程来源材料、代码依赖和教学数据按各自许可及课程授权使用，不套用模板商业密级，不对外发布共享来源。文档、接口协议、迁移、日志定位及演示步骤保持可维护；没有真实交易法律/监管合规认证要求。国际化不适用，界面和课程文档为中文；数据交换使用UTF-8。开放性通过本地HTTP/JSON和模拟文件定义，跨产品/大规模部署兼容需另验收。

输入为发布/课程交付内容，权限为小组/维护人员；输出为规格、接口、测试证据和演示资料。验收NFR-T09：无凭据/真实卡号/不授权来源公开，文档需求编号及协议一致，不把未知或未测项目写成通过。
