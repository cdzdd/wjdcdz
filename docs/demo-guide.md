# 基金销售与模拟交易平台：课程演示指南

这份指南用一位新客户、两张模拟银行卡和一只专用基金，演示“开户 → 受理 → 确认 → 持仓 → 赎回 → 回款”的完整流程。主线约需15分钟操作，启动与构建时间另计；后面的扩展场景按课程需要选择。

所有金额、银行卡和产品均为教学模拟数据。文中的日期是**平台业务日期**，不是电脑当天日期；无需等待现实时间经过一天。

进入“净值发布”，选择刚创建的基金，**先发布历史参考净值**：日期`2026-10-16`、单位净值`1.200000`。当前业务时钟已经晚于该日15:10，允许发布；这条数据用于申购页面预估。新基金没有参考净值时，页面无法完成预估并提交申购。

讲解重点：“参考净值用于展示预估；最终成交必须使用申请归属日的净值。”

### 步骤B：开户、风险测评和两张卡（课程客户）

1. 注册并登录`course_demo_1019`，进入“账户设置 → 客户档案”，点“开通模拟客户账户”。
2. 进入“风险测评”，回答全部10题。为本次教学操作便于演示，可每题选第3项“均衡 / 有一定了解”，提交后得到R3，与R2产品匹配。
3. 进入“银行卡与资金”，绑定首卡：模拟银行名称`模拟工商银行`、模拟持卡人`课程演示客户`。本文称为**A卡 / A交易账户**。首次有效绑卡获得`100,000.00`模拟资金。
4. 绑定第二张：银行名称`模拟建设银行`，持卡人仍为`课程演示客户`。本文称为**B卡 / B交易账户**，初始余额为`0.00`。
5. 点B卡的“充值”，输入`10000.00`并确认。A卡不充值。

记录两张卡显示的SIM标识和交易账户编号；后续通过银行名称与账户编号选择。卡ID、交易账户ID由系统生成，不照抄其他人的编号。

此时应看到：A可用`100,000.00`、B可用`10,000.00`，两者冻结均为零。可以先把B“设为默认”，说明默认只是选择偏好，每笔交易仍须明确来源账户。

“基金市场”搜索`课程演示债券 A`，进入详情，点“申购”。两笔分别操作：

| 来源 | 购入金额（元） | 操作 |
| --- | ---: | --- |
| A：模拟工商银行 | `12012.00` | 选择A账户 → 预估费用与份额 → 确认提交申请 |
| B：模拟建设银行 | `6006.00` | 选择B账户 → 预估费用与份额 → 确认提交申请 |

进入“交易记录”刷新：两笔归属交易日均为`2026-10-19`，状态为待确认。进入“银行卡与资金”刷新：

| 账户 | 可用资金（元） | 冻结资金（元） |
| --- | ---: | ---: |
| A | `87,988.00` | `12,012.00` |
| B | `3,994.00` | `6,006.00` |

提交申请只是受理和冻结，尚未生成最终持仓。到“基金账户”标签查看：两张卡购买同一登记机构产品，复用同一个TA基金账户，但资金与持仓仍按交易账户分别记录。

可选撤单演示：在A账户额外申购`1001.00`，立即到“交易记录”点该笔“撤单 → 申请撤单”。状态变为已撤销，A的可用及冻结恢复到上表数值。必须在当日15:00之前、未确认时操作，不撤掉主线两笔。

### 步骤D：发布申请日净值并确认（管理员）

1. 业务时钟推进到`2026-10-19 15:10:00`。
2. “产品与数据 → 净值发布”，发布`课程演示债券 A`：日期`2026-10-19`、净值`1.200000`。
3. 业务时钟推进到`2026-10-20 09:10:00`。
4. “交易与任务 → 任务中心”，任务类型选“交易确认（CONFIRM）”，**业务日期手动填`2026-10-20`**，点“执行任务”。

可选“缺净值等待”演示：暂缓第2项发布，在10月20日先执行CONFIRM，会保留两笔待确认并显示缺少所属交易日净值；仍在10月20日补发**10月19日**净值1.2，再次CONFIRM即完成。不要补成10月20日的净值来替代申请日。

切换客户窗口，到“交易记录”和“资产总览”刷新。两笔申购已完成，冻结资金归零，预期成交如下：

| 账户 | 申请金额（元） | 申购费用（元） | 净申购金额（元） | 成交净值 | 持仓份额 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A | `12,012.00` | `12.00` | `12,000.00` | `1.200000` | `10,000.0000` |
| B | `6,006.00` | `6.00` | `6,000.00` | `1.200000` | `5,000.0000` |

算法为净申购金额＝申请金额÷(1＋费率)，金额保留两位、份额保留四位；本例特意选择无复杂尾差的输入。客户持仓成本包含已支付申购费用。

任务记录统计的是本次处理项，干净环境中这次成功确认2笔。演示库如有其他客户待处理，批次合计可能更大；请按本次客户的订单和账户核对。

### 步骤E：双账户赎回、成交后等待付款

管理员把业务时钟推进到`2026-10-21 14:00:00`。客户在基金详情点“赎回”，分别申请A账户`2000.0000`份、B账户`1000.0000`份；每笔都先预估，再提交。

如需展示整组受理，可用“资产总览 → 多账户汇总赎回”**替代这两笔手工申请**：选择同一基金，A填2000、B填1000，点“逐账户预估 → 提交整组申请”。金额与后续时点相同，“交易记录”会显示赎回组，点组号查看两个独立子单；不要两种方式重复提交。

此时预估仍可能使用最近公布的10月19日净值1.2，**预估回款不等于最终回款**。提交后，A冻结2000份、B冻结1000份，钱包尚未收到钱。

管理员按顺序操作：

1. 时钟推进到`2026-10-21 15:10:00`，发布本基金10月21日净值`1.260000`。
2. 时钟推进到`2026-10-22 09:10:00`，执行“交易确认（CONFIRM）”，业务日期`2026-10-22`。

客户刷新后，赎回变为待到账；A剩8000份、B剩4000份，冻结份额归零。后台“待支付与路由”出现两笔回款，计划支付日均为`2026-10-26`，客户资产中的待到账保留对应金额。

| 账户 | 赎回份额 | 成交净值 | 毛回款（元） | 实际赎回费率 | 费用（元） | 净回款（元） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A | `2,000.0000` | `1.260000` | `2,520.00` | 1.5% | `37.80` | `2,482.20` |
| B | `1,000.0000` | `1.260000` | `1,260.00` | 1.5% | `18.90` | `1,241.10` |

**为什么产品基础费率为0仍有费用？** 本平台非货币基金持有不足7个自然日时，赎回费率至少1.5%。取得日是10月20日实际确认日，赎回归属日为10月21日，属于短期持有；不能用基础费率0推断此次无费用。付款T+3从赎回申请日10月21日起数开放日：22、23、26。

### 步骤F：展示等待，随后原路到账

1. 管理员把时钟推进到`2026-10-26 09:10:00`，执行“款项支付（PAY）”，业务日期`2026-10-26`。
2. 尚未达到09:30付款时点，两笔均等待；点任务“结果详情”查看尚未到支付时间的说明。客户钱包不应提前增加。
3. 时钟推进到`2026-10-26 10:00:00`，再次执行PAY，日期仍为`2026-10-26`。
4. 客户刷新“银行卡与资金”“交易记录”“资产总览”，确认两笔赎回已完成；资金回到各自来源交易账户。

主线完成且没有另做充值、提现或扩展交易时，最终检查：

| 项目 | A账户 | B账户 |
| --- | ---: | ---: |
| 可用现金（元） | `90,470.20` | `5,235.10` |
| 冻结现金（元） | `0.00` | `0.00` |
| 基金份额 | `8,000.0000` | `4,000.0000` |
| 按最新净值1.26的市值（元） | `10,080.00` | `5,040.00` |
| 待到账（元） | `0.00` | `0.00` |

总资产应为`110,825.30`元。初始资金加B充值合计110,000元，净增加825.30元，已扣申购费18元和短持赎回费56.70元。

本指南主线的双卡输入、共享TA账户、确认成交、付款时点、去重和最终金额已在独立测试环境实际核对；扩展章节的条件及操作依据当前平台实现整理。

再执行一次相同PAY：没有重复到账，页面显示“无待处理业务”。这是去重后的正常结果，并非需要补造成功数量。最后在客户“资金流水”查看冻结、确认核销、付款入账记录，并在后台“运营与审计 → 账务对账”检查账务一致性。

## 3. 扩展场景：按日期选择演示

以下场景从主线结束后继续，按日期向前安排。可以只选一项；如果同时演示多个，先完成各项“准备”，再推进时钟。各项会改变余额和持仓，主线末尾的固定金额只用于扩展操作前核对。所有表单自带的旧日期都要改成下文日期。

**组合演示按下面的时间表交叉操作，不要做完一个章节再倒退日期做另一个。** 同一基金、同一天的净值只发布一次；定投和转换共用主线基金10月27日的`1.260000`净值，后续步骤直接复用。

| 业务时点 | 组合演示操作 |
| --- | --- |
| 10月26日10:00至15:00前 | 完成主线到账和可选换卡；准备C卡及两条定投、转换目标基金及关系、分红事件、货币基金及其申购、两只募集基金及其认购 |
| 10月27日09:10 | CONFIRM确认货币基金申购 |
| 10月27日10:00 | SIP执行两条定投；分别处理募集成立与失败，再PAY失败认购退款 |
| 10月27日14:00 | 从A提交1000份基金转换 |
| 10月27日15:10 | 发布主线基金净值1.26、转换目标净值1.0；各基金各发布一次 |
| 10月28日09:10及之后 | CONFIRM处理定投申购及转换；展示定投暂停、恢复后终止两条计划；发布货币基金10月28日万份收益0.5 |
| 10月29日09:10 | 生成分红权益快照；MONEY处理10月28日收益 |
| 10月29日15:10 | 发布主线基金除息净值1.24 |
| 10月30日10:00 | 执行分红，再PAY；待全部相关业务结清后，才进行终止、清盘与清盘PAY |

只选其中一项时，按该小节操作即可；权限、现金更正与对账可穿插展示，最终清盘留在最后。

### 3.1 收款受阻与受控换卡（可插入主线步骤F）

在10月26日10:00第一次成功PAY之前，管理员在“客户与账户 → 交易账户与卡”找到课程客户A账户，点“设置收款受阻”，理由填`课程演示：模拟旧卡无法收款`。执行PAY后，B先到账，A显示等待及收款受阻原因；A的2482.20元仍是应收，不丢失。

客户在“银行卡与资金”对A卡点“申请换卡”，保持原银行`模拟工商银行`和持卡人`课程演示客户`，理由`旧卡损坏，申请同银行同名换卡`。管理员进入“客户与账户 → 换卡核准”，核准理由填`已完成教学同名同银行核验`。

再次PAY：A到账。观察A的**交易账户编号和余额保留**，SIM卡标识及绑定版本变化；“待支付与路由”保留历史来源卡、当前付款目标及换卡授权。把B设为默认不能替代这项授权。若不演示换卡，管理员“恢复收款”后再次PAY也可完成主线。

### 3.2 定投成功与真实失败

准备时钟仍为10月26日：客户额外绑定C卡`模拟农业银行`，同名持卡人，不充值；后来绑卡不会再发10万元。进入“定投计划 → 创建计划”，创建两条：

| 参数 | 成功计划 | 失败计划 |
| --- | --- | --- |
| 基金 | 课程演示债券 A | 课程演示债券 A |
| 固定扣款交易账户 | A | C（余额0） |
| 每期金额 | `1001.00` | `1001.00` |
| 周期 / 星期 | 每周 / `2`（周二） | 每周 / `2` |
| 开始日期 | `2026-10-27` | `2026-10-27` |

管理员推进到`2026-10-27 10:00:00`，执行SIP，日期10月27日。A生成申购订单，C记当期失败，原因是该账户可用余额不足；A有钱不代表C可以借用。重复SIP不会重复扣A，也不会自动补扣C本期。

推进到10月27日15:10，发布主线基金该日净值`1.260000`；10月28日09:10执行CONFIRM。成功计划的净申购1000元、新增`793.6508`份。客户可展示暂停、恢复和终止；演示后终止两条计划，避免下周继续生成业务。

### 3.3 同账户基金转换

准备时钟为10月26日：管理员新建`DEMOCONV26 / 课程转换目标债券 A`，管理人和登记机构与主线基金相同，BOND、R2、OPEN、申购费率`0.001`、赎回基础费率`0`、最低100元/1份、开放申赎。先发布10月23日参考净值`1.000000`，再到“收益与生命周期 → 转换关系”启用“主线基金 → 新目标基金”方向。

10月27日14:00，客户“认购与收益 → 基金转换”：A账户、转出主线基金、转入新目标基金、`1000.0000`份，先预估再提交。10月27日15:10发布双方当日净值：主线`1.260000`、目标`1.000000`；10月28日09:10执行CONFIRM。

本例从主线10月20日取得的批次转出，持有已满7日，赎回基础费率0，两只申购费率相同，补差费0；新增目标份额`1260.0000`。原基金减少1000份，**钱包现金不经一次提现再充值**，目标持仓仍在A账户，历史来源可追溯。若先改变了持仓批次，实际费用与份额按交易记录核对。

## 4. 演示收尾和常见问题

可用一句话串起课程主线：“同一客户可以有多张卡，各有交易账户；同一TA基金账户可复用，资金、份额、原交易来源和回款授权仍分别记录。申购确认产生份额，赎回确认产生应收，付款完成才增加现金。”

| 现象 | 检查与处理 |
| --- | --- |
| 新基金不能预估申购 | 先发布前一开放日参考净值；不是只创建产品就能在界面提交 |
| 净值发布时间过早 | 时钟先推进到所属开放日15:10；净值日期仍填申请归属日 |
| 净值提示已发布、不能覆盖 | 自动扫描或之前已发布过；保留原记录。换新产品与未来日期，或按已发布实际净值重算，不删成交数据 |
| 批次显示无待处理业务 | 确认任务类型、日期、业务时钟及订单计划日期；业务已处理过时重复扫描不会再次成交或到账 |
| 确认仍等待 | 检查是否到T+1日09:00，是否存在申请归属日净值；最新其他日期净值不能代替 |
| 付款仍等待 | 检查是否到T+3日09:30、来源卡是否可收款、是否需换卡授权 |
| 切换窗口后角色变化 | 用独立浏览器或普通窗口＋隐私窗口，同一普通会话共享登录 |
| 表格合计与本文不同 | 查看是否混入其他客户、自动任务或扩展交易；按本次用户名、产品和账户分别核对 |

正式展示只需要主线步骤A至F，再选择1至2项扩展即可。建议截图保留“申购受理冻结”“双卡持仓”“赎回待到账”“付款成功与逐账户流水”四个节点，辅以任务结果详情和对账结果。
